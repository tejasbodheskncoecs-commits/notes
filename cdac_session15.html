Error Handling and Exceptions

When something goes wrong inside a stored procedure, a handler decides what happens next. Learn what errors are, how handlers catch them, and how to raise your own errors with SIGNAL.

1. Errors, warnings, exceptions and conditions

Real-life first: a college office receives a form with a student number that is already registered. The clerk does not ignore it. The clerk stops, says "already exists", and continues with the next form. That reaction is what error handling does in code.

Error

something failed

A statement could not be completed. Example: inserting a student id that already exists. MySQL stops that statement and raises an error.

Warning

completed with a note

The statement finished, but MySQL has a note about it. Example: a value was cut to fit a column. The work is done, and a warning is recorded.

NOT FOUND

no row

A SELECT ... INTO or a cursor FETCH found no row. This is not a failure of the statement. It means there was no data to read.

Exception and SQL condition

the umbrella words

A condition is any named situation that MySQL can report: an error, a warning, or NOT FOUND. An exception is a condition that interrupts normal flow, usually an error. A handler is written to react to conditions.

2. What is a handler, and why do we need it?

Handler

definition

A handler is a declaration inside a BEGIN…END block that says: when this condition happens, run this statement. Without a handler, an error in a stored procedure stops the procedure and the error goes back to the caller.

Analogy: a fire alarm. The alarm (condition) is set up in advance (DECLARE HANDLER), and it tells the building what to do when smoke appears.

CONTINUE handler

keep going

After the handler's statement runs, execution continues with the statement that comes after the one that raised the condition.

EXIT handler

leave block

After the handler's statement runs, execution leaves the BEGIN…END block where the handler was declared. In a procedure's top block, the procedure ends.

UNDO handler

not in MySQL

The SQL standard describes an UNDO handler, which would undo the work of the block. MySQL 8.0 does not support UNDO handlers. Writing DECLARE UNDO HANDLER gives a syntax error. Use EXIT with ROLLBACK for a similar result.

MySQL 8.0 supports: CONTINUE and EXIT only. UNDO is not supported.

3. Condition categories, error codes and SQLSTATE

A handler can name a condition by category, by error code, by SQLSTATE, or by a name you create.

SQLEXCEPTION

any real error

Covers every SQLSTATE class that is not 00 (success), 01 (warning) or 02 (NOT FOUND). Use it as a general safety net.

SQLWARNING

SQLSTATE 01…

Covers warnings: SQLSTATE values that start with 01, such as a value truncated during an insert.

NOT FOUND

SQLSTATE 02…

Covers SQLSTATE values that start with 02, such as SELECT ... INTO with no matching row, or FETCH after the last cursor row.

Error code

MySQL number

A MySQL-specific number. Example: 1062 means duplicate entry. You see it as "ERROR 1062 (23000)" in the client.

SQLSTATE

5-character standard code

A standard code used across databases. Example: '23000' is an integrity-constraint violation (this group includes duplicate keys). '45000' is the generic code for user-defined errors raised with SIGNAL.

Named condition

your own name

You can give a code a name with DECLARE … CONDITION FOR, then use that name in a handler. This makes the code easier to read.

4. Writing handlers and declaration order

Handler syntax

MySQL 8.0
DECLARE handler_action HANDLER FOR condition_value [, condition_value] ...
    statement;

-- handler_action : CONTINUE | EXIT
-- condition_value: SQLEXCEPTION | SQLWARNING | NOT FOUND
--                | SQLSTATE 'sqlstate_value' | error_code | condition_name

Line by line: DECLARE starts the declaration. CONTINUE or EXIT is the action. HANDLER FOR introduces the condition(s). statement is what runs, and it may be a BEGIN…END block.

Named condition syntax

DECLARE … CONDITION
DECLARE condition_name CONDITION FOR condition_value;

-- Example
DECLARE dup_key CONDITION FOR 1062;
DECLARE CONTINUE HANDLER FOR dup_key SELECT 'Duplicate!' AS message;

DECLARE CONDITION only gives a name to a code. It does nothing by itself. A DECLARE HANDLER is what reacts to the condition.

Declaration order inside BEGIN…END

must know
1. Variables and named conditions
DECLARE v_x INT; DECLARE dup_key CONDITION …
2. Cursors
DECLARE cur CURSOR FOR …
3. Handlers
DECLARE … HANDLER …
4. Statements
SET, SELECT, IF, OPEN, CALL …
Declaring a variable, condition, cursor or handler after an executable statement is a syntax error. Keep all DECLARE lines together at the top of the block.

Scope and behaviour

where it works
  • A handler applies to statements in the BEGIN…END block where it is declared, and in blocks nested inside it.
  • Handlers work in stored procedures and in stored functions.
  • A handler on NOT FOUND catches missing rows from SELECT … INTO and from cursor FETCH.
  • If several handlers match one error, the most specific one is used: error code first, then SQLSTATE, then the general category.

6. SIGNAL and RESIGNAL

SIGNAL

raise an error

Starts a new error or warning yourself. Use SIGNAL SQLSTATE '45000' for a custom error, and set the text with SET MESSAGE_TEXT.

SIGNAL SQLSTATE '45000'
    SET MESSAGE_TEXT = 'Marks must be 0 to 100';

RESIGNAL

pass it on

Used only inside a handler. It raises the error again, so the caller (or an outer handler) receives it. You can change the message.

DECLARE CONTINUE HANDLER FOR SQLEXCEPTION
BEGIN
    RESIGNAL SET MESSAGE_TEXT = 'Could not save record';
END;
Exam trap: RESIGNAL outside a handler is an error. A RESIGNAL inside a CONTINUE handler re-raises the error, so unless an outer handler catches it, the procedure stops and the caller gets the error.

CDAC exam preparation

Common traps in MCQs

read carefully
  • UNDO handler looks correct but is not supported in MySQL 8.0.
  • CONTINUE does not stop the procedure; EXIT leaves the block.
  • DECLARE CONDITION does not handle anything. Only DECLARE HANDLER reacts.
  • Handler after a statement is a syntax error.
  • SQLSTATE '23000' covers more errors than error 1062.
  • RESIGNAL only works inside a handler.

Important facts to memorise

facts
  • MySQL 8.0 handler actions: CONTINUE, EXIT.
  • NOT FOUND = SQLSTATE 02…; warnings = 01…
  • 1062 = duplicate entry (23000); 1644 = SIGNAL (45000).

Beginner mistakes and fixes

fix
  • Mistake: forgetting ROLLBACK in a transaction handler. Fix: add it before the message.
  • Mistake: expecting CONTINUE to stop. Fix: use EXIT to leave the block.
  • Mistake: no NOT FOUND handler after SELECT INTO. Fix: add one.

Final revision sheet

  • Handler syntax: DECLARE CONTINUE|EXIT HANDLER FOR condition statement;
  • Actions: CONTINUE runs the next statement; EXIT leaves the block. UNDO is not supported.
  • Categories: SQLEXCEPTION (errors), SQLWARNING (01…), NOT FOUND (02…).
  • Codes: error code 1062 = duplicate entry, SQLSTATE 23000. 1644 = SIGNAL, SQLSTATE 45000.
  • Named condition: DECLARE name CONDITION FOR 1062; then use name in a handler.
  • Order: variables and conditions, then cursors, then handlers, then statements.
  • SIGNAL raises an error. RESIGNAL re-raises inside a handler only.
  • MCQ traps: UNDO, DECLARE CONDITION does not act, handler after statements, RESIGNAL outside handler.
  • MySQL 8.0 limits: no UNDO handlers; handlers must be declared before statements.
