Cursors in MySQL

1. Introduction to cursors

Start here. Do not skip this part, because every later topic depends on it.

What is a cursor?

basic meaning

A query such as SELECT name, marks FROM students returns a result set: a list of rows. Normally, SQL hands you the whole list at once.

A cursor is a pointer that moves through that result set one row at a time. You use it inside a stored procedure, where you can write code (IF, LOOP, variables) that handles each row.

Analogy: the result set is a book with 6 pages. A cursor is a bookmark. You open the book, turn one page at a time (FETCH), read the page, and stop when the book ends.

Why do we need cursors?

why

Some tasks need row-by-row decisions. For example: give each student a grade based on their own marks, or send a message to each student who failed.

Why not always a normal SELECT?

limit

A normal SELECT returns the rows, but it cannot run IF/ELSE logic on each row, store a value per row in variables, or run custom code for each row. A cursor gives you that per-row control.

Normal SELECT vs cursor

PointNormal SELECTCursor
Where it runsAnywhere (a query window, a program)Only inside a stored procedure (or function/trigger)
How rows are returnedAll rows as one result setOne row at a time, on each FETCH
Per-row logicNot possible (except CASE inside the query)Yes, with IF, variables and loops
Typical speedFast (set-based)Slower for large data
Best forFiltering, joining, summarisingRow-by-row processing with custom logic

Advantages

pros
  • Process rows one by one with custom logic.
  • Keep row-by-row logic inside the database.
  • Easy to read for beginners who think step by step.

Disadvantages

cons
  • Usually slower than one set-based statement.
  • More code (DECLARE, OPEN, FETCH, CLOSE, handler).
  • Easy to make mistakes at the end of the data.

Practical use cases

examples

Grade calculation per student, bank interest for each account, sending reminders row by row, checking stock and reordering item by item, and salary processing for each employee.

3. Types of cursors

Important: sensitivity, updateability and scrolling are three separate properties, not four mutually exclusive types. A single cursor has one value for each property. The four concepts below describe those properties.

PropertyQuestion it answersConcepts
SensitivityDoes it see changes made to the table after it was opened?Asensitive, Insensitive
UpdateabilityCan rows be updated through the cursor?Read-only (or updatable)
ScrollingCan it move backwards or jump, or only forward?Non-scrollable (or scrollable)
MySQL 8.0 rule: stored-program cursors are asensitive, read-only and non-scrollable. In a normal stored procedure you cannot explicitly choose INSENSITIVE or SCROLL. The insensitive idea is only a concept to understand.

3. Important MySQL stored procedure rules

Declaration order inside BEGIN…ENDWhy
1. Variables (DECLARE v_name ...)Variables must exist before anything uses them.
2. Cursors (DECLARE cur CURSOR FOR ...)A cursor query can use variables declared above.
3. Handlers (DECLARE CONTINUE HANDLER ...)A handler can refer to variables and cursors declared above.
4. Executable statements (SET, OPEN, FETCH, IF, ...)All declarations must come before any statement that runs.

Common beginner confusions

PairKey difference
Cursor vs SELECTSELECT returns all rows at once. A cursor reads them one at a time inside a procedure.
Cursor vs stored procedureA procedure is the container with the code. A cursor is one tool used inside it.
Cursor vs loopThe cursor gives the rows. The LOOP (or WHILE) repeats the code that handles each row.
DECLARE vs OPENDECLARE only defines the cursor and its query. OPEN runs the query and prepares the rows.
OPEN vs FETCHOPEN happens once. FETCH happens once per row.
FETCH vs SELECTFETCH reads the next row of an open cursor into variables. SELECT returns rows to the user.
LOOP vs WHILELOOP runs until you LEAVE. WHILE checks its condition before each run.

Why a NOT FOUND handler?

essential

When there are no more rows, FETCH does not change the variables. Without a handler, MySQL raises error 1329 and the procedure stops. The handler catches the NOT FOUND condition and sets a flag so your code can leave the loop.

FETCH after the last row

what happens

With the handler: the flag v_done becomes TRUE and the procedure continues. Without it: error 1329 "No data - zero rows fetched" stops the procedure. The variables keep the last values that were fetched.

Why doesn't a cursor print records?

important

FETCH only copies the row into variables. Nothing is shown to the user. To display data, use a SELECT inside the loop, as in the labs.

Why are cursors often slower?

performance

A cursor handles rows one at a time in procedural code. One set-based statement lets the database process all matching rows in an optimised way.

Important theory questions

  2. Explain the four lifecycle steps in order.
  3. What is the role of DECLARE CONTINUE HANDLER FOR NOT FOUND?
  4. Why is the done flag checked right after FETCH?
  5. Why are MySQL stored-program cursors asensitive, read-only and non-scrollable?
  6. Why is a LOOP the natural choice when the number of rows is unknown?

Short revision notes

quick
  • Cursor = pointer to a result set, one row per FETCH.
  • Order: DECLARE → OPEN → FETCH (repeat) → CLOSE.
  • Handler sets v_done when no row is left.
  • Check v_done right after FETCH, before using the variables.

Interview questions (simple answers)

interview
  • Q: What is a cursor? A: A way to process rows one at a time in a stored program.
  • Q: Why is a cursor slow? A: It does row-by-row work in code, not one set-based statement.
  • Q: What happens if you FETCH past the end? A: With the handler, v_done is set. Without it, error 1329.

Important MySQL cursor rules for MCQs

must know
  • Cursors work only inside stored procedures, functions and triggers.
  • MySQL stored-program cursors are asensitive, read-only and non-scrollable.
  • Declare order: variables, then cursors, then handlers.
  • A cursor must be OPENed before FETCH, and CLOSEd when finished.
  • DECLARE CONTINUE HANDLER FOR NOT FOUND sets the flag at end of data.
  • Loop labels and nested BEGIN…END blocks are allowed.
