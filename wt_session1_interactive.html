Web applications

An application is a program that does a useful job for a user. A web application is used through a browser, while the app itself runs on a server.

Client, server and database

Three roles work together. Learn them with an online shop: you (the client) ask, the shop's server answers, and the database remembers the products and orders.

Client

asks

The program that sends a request. Usually the browser on your phone.

Server

answers

A computer or program that waits for requests and gives replies. It is always switched on.

Database

stores

An organised store of data such as users, products, prices and orders.

Application logic

rules

The rules of the app: is this password correct? Is the item in stock? Can this order be placed?

Important: a server does not hold everything. Some code runs in the browser (a dropdown opening), some on the server (password checks), and data may sit in a separate database machine.

Frontend development

Frontend is the part the user sees. HTML builds the structure, CSS styles it and JavaScript adds behaviour.

HTML

structure

HyperText Markup Language. Headings, paragraphs, images, links, buttons and forms. Not a programming language.

<h1>Welcome</h1>
<button>Add to Cart</button>

CSS

style

Cascading Style Sheets. Colours, fonts, spacing, borders and layout.

button {
  background: blue;
  color: white;
  border-radius: 6px;
}

JavaScript

behaviour

Button clicks, form checks, dropdowns and dynamic updates. Runs in the browser and, with Node.js, on the server.

button.onclick = () =>
  alert("Item added");

React.js

library

A JavaScript library for building user interfaces from reusable components. Like a LEGO brick: build one product card and reuse it for every product.

Angular

framework

A frontend web application framework with a full structure and built-in tools.

Tailwind CSS

utility CSS

A utility-first CSS framework: small ready-made classes added directly in HTML.

<button class="bg-blue-600 text-white px-4 py-2 rounded">

Backend development and databases

The backend works behind the scenes. Sensitive work, such as passwords, payments and prices, must happen on the server, because the browser code can be changed by the user.

Server-side

backend

Logic, passwords, orders and payments run on the server. Frontend checks are for convenience; backend checks are for security.

Node.js

JavaScript on server

A runtime that runs JavaScript outside the browser. Other backend languages include Java, Python and PHP.

MySQL

relational

Stores data in tables with rows and columns, linked by keys. Queried with SQL.

MongoDB

document

Stores flexible JSON-like documents grouped in collections.

URL, IP address and DNS

A URL is the full address. An IP address is a number that identifies a device. DNS turns a domain name into an IP address.

https://www.flipkart.com/search?q=mobile+phone
 │       │                │       │
 │       │                │       └─ query (search words)
 │       │                └───────── path (which resource)
 │       └────────────────────────── domain name
 └────────────────────────────────── protocol (secure HTTP)

IP example: 192.168.1.2 is a private address on a home network. It is not Flipkart's public address.

HTTP request methods

A method says what the client wants to do. It is a keyword in the request, not a programming-language method. Exact behaviour depends on the server and API design.

Method picker
PUT vs PATCH: PUT sends the whole new version of the resource. PATCH sends only the fields that change.

HTTP responses and status codes

A response has a status code, a reason phrase, headers and, when needed, a body. The first digit gives the category.

1xx

info

Informational: still working.

2xx

success

Your request worked.

3xx

redirect

Go somewhere else.

4xx

client error

Problem with the request or your access.

5xx

server error

The server or a service it depends on failed.

Remember: 4xx and 5xx are useful guidelines, not absolute proof of the cause. Check the message and logs before deciding. 401 = “who are you?”, 403 = “you are not allowed”.

GET · 200
GET /search?q=mobile+phone HTTP/1.1

HTTP/1.1 200 OK
Content-Type: application/json

The search words travel in the URL because searching retrieves information.

3 · Login failures

400 · 401 · 403

400 the password field is missing. 401 the password is wrong. 403 a logged-in customer opens the admin page.

4 · Server failure

500
POST /orders HTTP/1.1
Host: www.example-shop.com

HTTP/1.1 500 Internal Server Error

The request was valid. The server hit a bug while saving the order, so the fault is on the server side.

Revision

One-page recap of Session 1.

  • A web application runs on a server and is used through a browser.
  • Client asks, server answers, database stores data.
  • Cycle: browser → HTTP request → server (logic) → database (if needed) → HTTP response → browser shows the page.
  • HTML = structure, CSS = style, JavaScript = behaviour. React = UI library, Angular = framework, Tailwind = utility CSS.
  • Sensitive logic (passwords, payments, prices) belongs on the server. Node.js runs JavaScript on the server.
  • URL = full address. IP = number. DNS = domain name to IP.
  • GET retrieves · POST submits/creates · PUT replaces · PATCH changes part · DELETE removes · OPTIONS asks what is allowed.
  • 2xx success · 3xx redirect · 4xx client error · 5xx server error. 401 = authentication. 403 = authorisation. 500 = server failure.
