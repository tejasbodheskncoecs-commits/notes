Introduction to Web Technology

Learn this session from zero. You will learn what a web application is, how a browser and a server talk to each other, what HTML, CSS and JavaScript do, what a database is, and how to read HTTP requests and responses. Every idea uses one online shop, so the pieces connect.

Session 1 · 21 Oct 2026Live demosUnderstanding checksGlossary

Before you start: three everyday words

These words appear in every topic. Read them once here.

Program: a list of instructions that a computer follows, in a language the computer can run. A calculator app is a program.
Network: computers connected so they can send messages to each other. Your phone and your home router form a small network.
Internet: the large network that connects millions of networks across the world. When you open a shopping site, your message travels across the internet to the shop's computer.
Analogy: a program is a recipe, a network is the set of roads, and the internet is the national highway system connecting every city.
Understanding check: what is the difference between a network and the internet?

A network is any group of connected computers, such as the Wi-Fi at your home. The internet is the largest network, which joins many networks together. A home Wi-Fi is a network; it becomes part of the internet when your router connects to your provider.

1 · Web applications

What an application is, and why some are used in a browser.

Application (app): a program that does a useful job for a user. Examples: a calculator, a music player, an online shop.
Desktop application: an app you install on your own computer. It runs on your computer's hardware and operating system (for example Windows or Linux). Examples: MS Word, VLC.
Web application: an app you use through a browser. The main program runs on a server on the internet, and the browser shows you the screens.
Browser: a program such as Chrome, Edge or Firefox. It asks web servers for pages, receives the replies, and displays the pages to you. It understands HTML, CSS and JavaScript (explained in topic 4).
Why do web applications exist? Imagine Flipkart as a desktop app. Every customer would need to install it, and every price change would need an update on every computer. With a web application there is one copy on the company's server. Every customer uses a browser, and everyone sees the same prices at the same moment.

Why does the internet matter?

A web application on a server is far away from you. The internet carries the messages between your browser and that server. Without the internet, your browser could not reach the shop's computer.

Analogy: the internet is the road, your browser is the car that drives your request to the shop, and the shop's server is the counter that answers.
Do I always need the internet?

No. There are two different ideas that people mix up:

Internet access vs running a web app locally
Internet accessYour device can reach computers on the internet. Example: your phone on mobile data.
Running a web app locallyThe server and the browser are both on your own computer. The address localhost means "this computer itself". No internet is needed.

Developers often run a web app at http://localhost:3000 on their laptop. It is still a web application, because it uses a browser and the same web technology, but it is not reachable from anyone else.

Common mistake: "A web application always needs the internet." Correct: it needs a network connection to reach its server. That server can be on the internet, on your office network, or on your own computer.
Understanding check: a developer runs a shopping site at localhost and turns off the Wi-Fi. Does the site still open in the browser? Why?

Yes. The browser and the server are both on the developer's laptop. The browser sends the request to localhost, which points back to the same computer, so no internet is used. The site is still a web application, because it is delivered through a browser.

2 · Client, server and database

Three roles. Learn them with one online shop.

Client: the side that asks for something. In web technology, the client is usually the browser on your phone or laptop.
Server: the side that answers. It is a computer, or a program running on a computer, that waits for requests and sends replies. It stays switched on so that clients can reach it.
Database: an organised store of data, such as users, products, prices and orders. Data is kept there so it is not lost when the server restarts and can be searched quickly.
Application logic: the rules and steps of the app, written as code. Examples: "Is this password correct?", "Is this product in stock?", "Apply 10% off if the total is above ₹2000."
Shop analogy: you are the customer (client). The shop counter is the server. The staff who decide "yes, this item is in stock" follow the application logic. The storeroom ledger that records stock and orders is the database.
Why do web applications use servers?

1. One copy for everyone. The app is installed once, on the server.

2. One correct set of data. If prices were stored only on each phone, Flipkart could not show the same price to everyone, and it could not change a price for all buyers at once.

3. Security. Passwords and payments must be checked where the user cannot change the rules. The server is under the company's control.

4. Always available. The server stays on, so you can shop at any time.

What happens when thousands of people use the same site?

One server can handle many requests, but not unlimited ones. Big sites therefore run many servers, and a load balancer (a device that spreads incoming requests across servers) sends each request to one of them. The servers share a database system built for many requests. The user does not see any of this.

A server does not hold everything

The server does not necessarily contain all the code of the app or all its data. Some code runs in the browser (opening a dropdown when you click it). Some code runs on the server (checking your password). The data can sit in a separate database machine.

Client, browser, server, application and database

Common mistake: "The browser is the server." The browser is the client program. The server is the computer that answers.
Common mistake: "The database is the application." The application follows the rules; the database only stores and returns the data.
Understanding check: when you press "Place order", which part decides that the item is in stock?

The application logic on the server. It asks the database for the stock count, checks it, and only then saves the order. The browser just sends the request; it should not be trusted to decide stock.

3 · How a web application works (the whole cycle)

Example: you open Flipkart, search "mobile phone", and see matching products. Press Next to follow each step.

HTTP (HyperText Transfer Protocol): the set of rules the browser and the server use to talk. A protocol is simply an agreed set of rules, like the rules of a phone call: who speaks first, and how each side says hello and goodbye.
HTTP request: the message the browser sends. It says what it wants: a method (what to do), an address (which resource) and some extra details (headers).
HTTP response: the reply the server sends back. It has a status code (the result), headers and sometimes a body (the page or data).

Understanding check: at which step does the server ask the database? Why not in the browser?

At step 5, after the server has understood the search. Only the server can reach the database safely. The browser does not hold the product table, and if it could reach it directly, any user could read or change data they should not touch.

4 · Frontend development

Frontend is the part the user sees and uses in the browser. Three core languages build it.

House analogy: HTML builds the walls and rooms, CSS paints and decorates them, and JavaScript installs the switches and doors that react when you touch them.
HTML: HyperText Markup Language
HTML describes the structure of a page: which part is a heading, which is a paragraph, which is an image, which is a button. It uses tags written in angle brackets, such as <h1>. Most tags have an opening and a closing form: <p>text</p>.
HTML is not a programming language. It does not make decisions or calculations. It only says what each piece of content is.
<h1>Welcome</h1>A main heading. The browser shows large bold text.
<p>Price: ₹14,999</p>A paragraph of text.
<img src="phone.jpg" alt="phone">An image. src is the file to show; alt is text for people who cannot see the image.
<a href="cart.html">Cart</a>A link. href is where it goes.
<button>Add to Cart</button>A clickable button.
<form> … <input> …</form>A form with input boxes, such as a login form.
CSS: Cascading Style Sheets
CSS controls how the HTML looks: colours, fonts, spacing, borders and layout. A CSS rule has a selector (which element) and declarations (what to change), like this: button { color: white; }. "Cascading" means that rules can override each other, and the more specific rule wins.
color: white;Text colour.
background: #2563eb;Background colour (blue).
padding: 8px 14px;Space inside the box, around the text.
margin: 10px;Space outside the box, between boxes.
border-radius: 6px;Rounded corners.
font-size: 18px;Size of the text.
JavaScript: behaviour
JavaScript is a programming language that makes a page react: a button click runs code, a form is checked before it is sent, a dropdown opens, a cart count changes without reloading the page.
JavaScript can run in the browser (this topic) and on the server with Node.js (topic 5). The same language can be used on both sides.

Common error: the button does nothing. Usually the id in JavaScript does not match the id in HTML (for example buy versus Buy). Ids are case-sensitive.
Frameworks and libraries
Library: ready-made code you call when you need it. Framework: a structure that defines how your app is organised, and calls your code in a set pattern. The difference: with a library you decide the structure; with a framework the structure is decided for you.
React.js: a JavaScript library for building user interfaces. Its key idea is the component: a reusable piece of the page, such as a product card. You build one card and reuse it for every product. A LEGO brick is a component: build it once, place it many times.
Angular: a frontend web application framework. It gives a complete structure with built-in tools for forms, routing (moving between pages) and data, which suits large apps.
Tailwind CSS: a utility-first CSS framework. Instead of writing your own CSS rules, you add small ready-made classes in HTML. Example: class="bg-blue-600 text-white px-4 py-2 rounded" means blue background, white text, padding and rounded corners.
Which technology does what?

CSSStyle language. Look and layout.
JavaScriptProgramming language. Behaviour.
ReactJavaScript library. Reusable UI components.

Common mistake: "React and Angular are the same kind of thing." React is a library; Angular is a framework. "Tailwind replaces CSS." Tailwind is a faster way to write CSS; it still produces CSS.
Understanding check: a button in your page looks correct, but clicking it does nothing. Which technology is responsible for the click, and which one controls the blue colour?

The click is handled by JavaScript (an event handler that runs code). The blue colour is controlled by CSS. HTML only created the button.

5 · Backend development

The backend is the part that works behind the scenes, on the server. The user does not see it directly.

Backend development: building the server-side code, the database work and the rules that run on the server.
Server-side processing: work done on the server rather than in the browser. Example: checking a password against the stored record.
Runtime: the environment that runs code. The browser is a runtime for JavaScript on the frontend. Node.js is a runtime that runs JavaScript on a server.
Frontend logic vs backend logic
Where logic should live
Runs inFrontend: the browser. Backend: the server.
Can the user change it?Frontend: yes, the user can change the browser code. Backend: no.
ExamplesFrontend: show or hide a menu, check that a field is not empty. Backend: check the password, calculate the final price, save the order.
Trusted for important decisions?Frontend: no. Backend: yes.
Frontend checks give fast feedback ("please enter an email"). Backend checks make sure the rules really hold. A good site does both.
Why sensitive work belongs on the server
Try the simulator below. The price shown in the browser is data the user controls. If the server trusted it, a buyer could pay less than the real price.
Choose a scenario to see the request and the server's decision.
Shop analogy: the price tag on the shelf is written by the shop (server). If a customer could change the tag on the shelf, the shop would be cheated. The cashier (server) must check the real price.
Common mistake: "The browser checks the password safely." The browser is under the user's control. Only the server can check the password against the stored record.
JavaScript on the server: Node.js
Node.js lets JavaScript run on a server. Below is a complete tiny server. You do not need to run it to understand it; read the explanation.
const http = require('http');              // 1. load Node's built-in web-server tool
const prices = { phone1: 14999 };         // 2. the server's own price list
http.createServer((req, res) => {         // 3. for every incoming request, run this function
  res.writeHead(200, { 'Content-Type': 'text/plain' }); // 4. reply: "success", plain text
  res.end('Price: ' + prices.phone1);     // 5. send the body and finish the reply
}).listen(3000);                          // 6. wait for requests on port 3000
require('http')Loads the built-in tool that understands HTTP messages.
const prices = {...}The server keeps the real price itself. The browser never decides it.
createServer(function)Creates a server. The function runs once for every request it receives.
writeHead(200, …)Sends the status code 200 (OK) and a header saying the body is plain text.
res.end('Price: …')Sends the body "Price: 14999" and closes the reply.
listen(3000)Waits on port 3000 of this computer. A port is a numbered door on a computer; different programs use different doors.

Run it: save the code as server.js and run node server.js. Open http://localhost:3000 in your browser. Expected result: the page shows Price: 14999.

Common error: "port already in use". Another program is using port 3000. Stop it, or change the number to 3001.
Other backend languages
JavaScript with Node.js is one choice, not the only one. Java (for example with Spring), Python (Django, Flask), PHP (Laravel) and C# are also used. Companies choose based on their team and project.
Shopping example: backend tasks
What the backend does
Product searchReads the search words, asks the database for matching products, returns the list.

Order placementChecks stock, saves the order, reduces the stock count.

Understanding check: why should the server, not the browser, calculate the final price?

Because the browser code and the data it sends can be changed by the user. If the browser decided the price, a customer could send a lower one. The server holds the true price list and recalculates the total, so it can refuse a tampered price.

6 · Databases

Where the data lives, and why a web app needs one.

Database: an organised collection of data that can be searched, added, changed and deleted. Think of a well-arranged library: books are sorted and labelled, so you find them quickly.
Why do web apps need databases? To keep data after the server restarts, to store data for many users at once, to search quickly ("all phones under ₹15,000"), and to keep one correct copy.
Application vs database
ApplicationRuns the rules and features. Decides what to do. Example: "apply the discount if the total is above ₹2000."
DatabaseStores and returns the data. Example: the table that holds prices and orders.
Restaurant analogy: the application is the chef (decides and cooks); the database is the fridge (stores the ingredients). A chef cannot cook from an empty fridge, and a fridge does not cook.

MySQL and MongoDB
MySQL is a relational database. Data is stored in tables with rows and columns. Tables are linked by keys (for example, an order row stores the product id). You ask questions with SQL (Structured Query Language). SQL is covered in the DBT module.
MongoDB is a document-oriented database. Data is stored as documents in a flexible JSON-like format, grouped in collections. JSON (JavaScript Object Notation) is a text format that writes data as name–value pairs.
// MongoDB style: one order as one document
{
  "orderId": "O9",
  "user": "Asha",
  "items": [ { "product": "Phone X", "price": 14999 } ]
}
Relational vs document
Data shapeRelational: fixed tables. Document: flexible documents.
Links between dataRelational: keys and JOINs across tables. Document: often nested inside one document.
Good forRelational: clear structured data such as bank records. Document: changing shapes such as product details.
Common mistake: "MySQL is the application." MySQL is only the storage system; the shop's own program is the application.
Understanding check: in the table above, which table would the shop need to join to show "which product did user 1 buy"?

The orders table (which stores user and product) and the products table (which stores the product name and price) are joined on the product id. In a document database, the same information can be stored inside one order document instead.

7 · Client-server communication

Three words that appear in every web interaction.

Client: the program that asks for something (the browser).
Request: the message the client sends, asking for something. Example: "give me the home page".
Response: the message the server sends back with the answer. Example: the home page, or an error message.
The complete process: (1) the client sends a request; (2) the server processes it, running the application logic and maybe the database; (3) the server sends a response; (4) the client uses the response to draw or update the screen.

The request is "search for mobile phone", sent by the browser. The response is the list of phones (with status 200 OK), sent back by the server.

8a · URL, IP address and DNS

How the browser knows where to send the request.

URL (Uniform Resource Locator): the full address of a resource on the web. Example: https://www.flipkart.com/search?q=mobile+phone.
Domain name: a human-friendly name for a server, such as www.flipkart.com. People remember names more easily than numbers.
IP address: a number that identifies a device on a network. Example: 192.168.1.2. This particular form is a private address used inside a home or office network; it is not Flipkart's public address.
DNS (Domain Name System): the system that converts a domain name into an IP address. A DNS server is like a phone book: you look up a name and get a number.

Why use a name at all? Names are easy to remember, and the company can change its server addresses without changing the name you type.
Common mistake: "192.168.1.2 is Flipkart's address." That number is private, used inside a home network. The public address of a website is different.
Understanding check: you type www.flipkart.com. Which system finds the IP address, and what does the browser do next?

DNS finds the IP address. The browser then connects to that IP address and sends the HTTP request to it.

8b · HTTP request methods

A method is the first word of an HTTP request. It says what the client wants to do.

HTTP method: a keyword that describes the purpose of a request. It is not the same as a method in programming. In Java or JavaScript, a method is a function attached to an object; an HTTP method is a word in a web message.
Resource: a thing the server holds, such as a user profile, a product or a cart item. Methods act on resources.
Method picker
PUT vs PATCH
PUTSends the whole new version. Think: rewriting the whole form.
PATCHSends only the changed fields. Think: correcting one line on the form.
Common mistake: "PUT and PATCH do the same thing." With PUT, a missing field may be removed or reset. With PATCH, missing fields are left as they are. The exact behaviour depends on the server.
The exact behaviour of each method depends on how the server and API are designed. The descriptions here are the standard meanings.
Understanding check: you want to change only your phone number. Which method is right, and why would PUT be risky?

PATCH, because it sends only the phone field. PUT would expect the whole profile; if the request sends only the phone number, the other fields could be lost or reset.

9 · HTTP responses and status codes

The server's reply, and what its number means.

What a response contains
Status codeA three-digit number that says what happened. Example: 200.
Reason phraseShort text for people. Example: OK.
HeadersExtra information. Example: Content-Type: text/html says the body is an HTML page.
BodyThe actual content, when there is any. Example: the HTML of the page or JSON data.
Common mistake: "Every response has a body." Some responses have none. For example, 204 No Content means success with nothing to send.
The five categories (first digit)

1xx

info

Informational: still working.

2xx

success

Your request worked.

3xx

redirect

Go to another address.

4xx

client error

A problem with the request or your access. Usually the client's side.

5xx

server error

The server, or a service it depends on, failed. Usually the server's side.

These categories are useful guidelines, not absolute proof. Always read the message and, for developers, the server logs.
Scenario simulator: a login
Status code explorer
401 vs 403
401 Unauthorized"Who are you?" The server does not know you, or your login details are wrong or missing. Fix: log in.
403 Forbidden"I know who you are, and you are not allowed." Fix: you need different permission, not a new password.
Common mistake: "401 and 403 mean the same." They differ: 401 is about identity, 403 is about permission.
Understanding check: a customer opens the seller page while logged in as a normal customer. Which code, 401 or 403? Why?

403 Forbidden. The server already knows the customer (they are logged in). The problem is permission, not identity.

Practical examples: reading real messages

These HTTP messages are simplified illustrations written for learning. They are not captured from a real site.

Example 1: opening a website
GET / HTTP/1.1 Host: www.example-shop.com HTTP/1.1 200 OK Content-Type: text/html <!DOCTYPE html> … home page … </html>
GETThe method: "retrieve".
/The path: the home page of the site.
HTTP/1.1The protocol version used.
Host: …The header that names the site. One server can host many sites, so the browser says which one it wants.
200 OKThe status: success.
Content-Type: text/htmlThe header that says the body is an HTML page.
Example 2: searching for a product
GET /search?q=mobile+phone HTTP/1.1 Host: www.example-shop.com HTTP/1.1 200 OK Content-Type: application/json [ {"name":"Phone A","price":14999}, {"name":"Phone B","price":12499} ]
The search words travel in the URL after the ? (this part is the query string). The server reads q, asks the database, and returns the matches as JSON. Because searching only retrieves information, the method is GET.
Example 3: login failures
Case A (400): POST /login body: {"username":"asha"} → HTTP/1.1 400 Bad Request (password field missing) Case B (401): POST /login body: {"username":"asha","password":"wrong"} → HTTP/1.1 401 Unauthorized (identity not proven) Case C (403): GET /admin/orders Cookie: session=abc123 → HTTP/1.1 403 Forbidden (known user, no permission)
Explain each case in your own words: 400 says the request is incomplete; 401 says the password is wrong; 403 says you have no permission.
Note: many real sites show "wrong password" on the same login page with a 200 status and an error message. Some APIs use 401 exactly as above. The choice depends on the implementation.
Example 4: server failure
POST /orders HTTP/1.1 Host: www.example-shop.com Content-Type: application/json {"product_id": 77, "quantity": 1} HTTP/1.1 500 Internal Server Error
The request is valid, so the client did nothing wrong. The server hit a bug while saving the order. The user should retry later, and the developers should check the server logs.
Understanding check: why is this 500 and not 400?

400 would mean the request itself is broken (for example, a missing field). Here the request is valid, and the failure happened inside the server, so the correct category is 5xx.

Instructor viva questions

Try to answer each one aloud, then open the answer.

1. What is the difference between a desktop and a web application?

A desktop application is installed and runs on your computer. A web application runs on a server and is used through a browser. The developer updates a web application once, on the server.

2. Does every web application need the internet?

No. It needs a network to reach its server. If the server runs on your own computer (localhost), no internet is needed.

3. Name the seven steps of the request-response cycle.

1) User opens the site in a browser. 2) The browser sends an HTTP request. 3) The server receives it. 4) The application processes it. 5) The application may query the database. 6) The server prepares an HTTP response. 7) The browser receives it and shows or updates the page.

4. Why should password checking be done on the server?

Browser code and data sent from the browser can be changed by the user. Only the server, under the company's control, can be trusted to check the password against the stored record.

5. What is DNS and why is it needed?

DNS converts a domain name such as www.flipkart.com into an IP address, so the browser knows where to send the request. Names are easier to remember, and servers can move without changing the name.

6. What is the difference between PUT and PATCH?

PUT sends the whole resource and replaces it. PATCH sends only the changed fields.

7. What does 401 mean, and how is it different from 403?

401 Unauthorized: authentication is required or failed; the server does not know who you are. 403 Forbidden: the server knows you, but you are not allowed to access the resource.

8. Why is HTML not a programming language?

HTML only describes the structure and meaning of content. It does not make decisions, loops or calculations. JavaScript is the programming language of the web.

9. Name two backend languages other than JavaScript.

For example Java, Python, PHP or C#.

10. What is the role of the database in the cycle?

It stores the data (products, users, orders) and returns the matching rows when the server asks. The server decides what to do with them.

Scenario questions

Read the situation, decide, then open the explanation.

S1. A bank website receives a wrong password. Which code is most likely?

401 Unauthorized. The server cannot confirm the user's identity. Some sites show the error on a normal page, so the exact code can differ.

S2. A customer tries to open the seller dashboard. The account has no seller rights.

403 Forbidden. The server knows the customer and refuses access because of permission.

S3. Clicking "Pay now" fails because the payment service does not give a valid reply to the front server.

502 Bad Gateway. The front server, acting as a gateway, received an invalid reply from another service. The user did not make a mistake.

S4. A user changes only the phone number on the profile. PUT or PATCH?

PATCH, because only one field changes.

S5. During a big sale the server is overloaded and says "try again in 5 minutes".

503 Service Unavailable, possibly with a Retry-After header telling the browser when to try again.

S6. A customer types the shop's address but the site does not open, and the message says the server could not be found.

The problem is in DNS or the address itself. The browser could not turn the domain name into an IP address. Check the spelling of the domain and the network connection.

Glossary

Every important term of the session, in plain words.

Application (app)A program that does a useful job for a user.
Application logicThe rules and steps of an app, written as code.
BackendThe part of the app that runs on the server.
BrowserA program that requests web pages and displays them.
ClientThe side that asks for a service, often the browser.
ComponentA reusable part of a user interface, as in React.
CookieA small piece of data the browser stores to remember you between requests.
DatabaseAn organised store of data that can be searched and changed.
Desktop applicationAn app installed and run on your own computer.
DNSDomain Name System. Converts a domain name into an IP address.
Domain nameA human-friendly name for a server, such as www.flipkart.com.
FrontendThe part of the app the user sees, run in the browser.
FrameworkA structure that organises your app and calls your code in a set pattern.
HeaderExtra information in an HTTP message, such as Content-Type or Host.
HTMLHyperText Markup Language. Describes the structure of a page.
HTTPHyperText Transfer Protocol. The rules for requests and responses on the web.
HTTP methodA keyword that says what a request wants to do: GET, POST, PUT, PATCH, DELETE, OPTIONS.
IP addressA number that identifies a device on a network.
JavaScriptThe programming language that adds behaviour in the browser and, with Node.js, on the server.
JSONJavaScript Object Notation. A text format for data as name–value pairs.
LibraryReady-made code you call when you need it.
Load balancerA device that spreads requests across many servers.
LocalhostYour own computer, reached by the name localhost.
MongoDBA document-oriented database storing JSON-like documents.
MySQLA relational database storing data in tables.
NetworkComputers connected so that they can exchange messages.
Node.jsA runtime that runs JavaScript outside the browser, on a server.
PortA numbered door on a computer; different programs listen on different ports.
ProtocolAn agreed set of rules for communication, such as HTTP.
QueryA question sent to a database. Also the part of a URL after ? (the query string).
ReactA JavaScript library for building user interfaces from components.
RequestThe message the client sends to ask for something.
ResourceSomething the server holds, such as a product or a profile.
ResponseThe message the server sends back with the answer.
RuntimeThe environment in which code runs, such as the browser or Node.js.
ServerThe side that waits for requests and answers them.
Status codeA three-digit number in a response that says what happened.
StatelessEach HTTP request is handled on its own; the server does not remember the last one by itself.
Tailwind CSSA utility-first CSS framework: small ready-made style classes in HTML.
URLUniform Resource Locator. The full address of a resource.
Utility classA small CSS class that does one job, such as rounded corners.
