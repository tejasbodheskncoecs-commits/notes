1. What is a trigger?

Definition and purpose, in plain English.

Definition

simple

A trigger is a named block of SQL that is attached to a table. MySQL runs it automatically when a certain change happens to that table.

Purpose

why

Use triggers to keep data correct and to record changes automatically, without relying on every program to remember the rule. Example: a college office wants every new student mark checked, even if the data is entered from different forms.

Trigger vs stored procedure

key difference

A stored procedure runs only when you write CALL. A trigger runs automatically because of an INSERT, UPDATE or DELETE, and you cannot CALL it.

BEFORE

runs first

Runs before the change. Use it to check data or set NEW values. Use SIGNAL to stop the change.

AFTER

runs last

Runs after the row is written. Use it to log changes or update another table. You cannot change NEW here.

4. INSERT, UPDATE and DELETE events

A trigger is tied to one table and one event. Three events exist.

INSERT

new row

Fires when a new row is added. Example: a new student is registered.

UPDATE

changed row

Fires when an existing row changes. Example: a student's marks are corrected.

DELETE

removed row

Fires when a row is removed. Example: a student leaves the college record.

6. Row-level triggers and FOR EACH ROW

In MySQL, every trigger is row-level: it runs once for each row that the statement changes.

Rows changed by one statement
3 rows

Example: INSERT INTO students VALUES (...), (...), (...); changes 3 rows.

Timing vs row level

don't mix these up

Timing answers when: BEFORE or AFTER the change. Row level answers how often: once per affected row. A BEFORE INSERT trigger on a 3-row insert fires 3 times, and so does the AFTER INSERT trigger.

8–9. CREATE TRIGGER syntax and DELIMITER

CREATE TRIGGER

syntax
CREATE TRIGGER trigger_name
BEFORE INSERT ON students      -- timing + event + table
FOR EACH ROW                   -- row-level
BEGIN
    -- statements
END;

Line by line: trigger_name is the name you choose. BEFORE INSERT ON students says when and on which table. FOR EACH ROW makes it run per row. BEGIN ... END wraps the body.

Also useful: SHOW TRIGGERS; DROP TRIGGER trigger_name;

DELIMITER

command-line client

In the MySQL command-line client, the semicolon normally ends a statement. A trigger body has semicolons inside it, so the client would stop too early. DELIMITER // changes the end marker to // while you type the trigger, then DELIMITER ; changes it back.

DELIMITER //
CREATE TRIGGER before_student_insert ... END //
DELIMITER ;
💡 Use DELIMITER even when the body is a single line ending with a semicolon. Without it, the client ends CREATE TRIGGER at that first semicolon.

10. Raising an error with SIGNAL SQLSTATE '45000'

Used inside a BEFORE trigger to stop an invalid change. The row is not written.

SIGNAL SQLSTATE '45000'
SET MESSAGE_TEXT = 'Marks must be between 0 and 100';

'45000' is the generic code for a user-defined error. MESSAGE_TEXT is the message the user sees.

One-page revision summary

  • Trigger = SQL attached to a table that runs automatically on INSERT, UPDATE or DELETE.
  • BEFORE runs first: check data, set NEW values, or stop with SIGNAL. AFTER runs last: log changes or update other tables.
  • Six combinations: BEFORE/AFTER × INSERT/UPDATE/DELETE.
  • FOR EACH ROW: MySQL triggers are row-level, so they fire once for each affected row.
  • NEW = row after change (INSERT, UPDATE). OLD = row before change (UPDATE, DELETE). Only BEFORE triggers can change NEW.
  • DELIMITER // lets the body keep its semicolons. Reset with DELIMITER ;.
  • SIGNAL SQLSTATE '45000' raises a custom error. Use it in BEFORE triggers to block the change.
  • Traps: a trigger cannot change its own table; TRUNCATE does not fire DELETE triggers; you cannot CALL a trigger.
